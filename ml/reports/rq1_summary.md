## Comparison to the paper (family level, not names)

The paper's 6 core metrics are SciTools **Understand** metrics (size family:
CountStmtExe, CountLineCode, CountDeclClass; cyclomatic family: SumCyclomatic,
SumCyclomaticModified, AvgCyclomaticModified). None of these exist in
SmellyCode++, so a name-level intersection is empty **by construction** - we
compare families instead:

- **Size dominates, exactly as in the paper.** Our entire strict consensus is
  size-scaled: `Logical Lines` (direct size) plus the Halstead volume/length
  metrics (`Total Operands`, `Vocabulary`, `Length`, `Calculated Length`) which
  all grow with program size. The paper's top metric family is likewise size
  (CountStmtExe / CountLineCode).
- **Cyclomatic complexity enters at the 4-of-5 level**, mirroring the paper's
  second core family. It is rank 2-4 in LinReg, LogReg and XGBoost and top-6 in
  permutation.
- **Verdict: the pattern replicates.** Despite a different target (code smells
  vs security bugs) and a different metric toolkit (Halstead vs Understand), the
  same two families - size and cyclomatic complexity - carry the signal.

## Caveats (the fix track)

- **Coefficient rankings are unstable here.** 39 metric pairs have |r| > 0.9
  (several exactly 1.0: `Bugs` = Volume/3000, `Time Required` = Effort/18), so
  linear/logistic coefficient mass splits arbitrarily among near-duplicates.
  Prefer the tree / permutation / SHAP rankings. (PAPER_REVIEW item 4.)
- **Boruta confirms all 14 features** as relevant (every metric carries some
  signal), so its discrimination comes only from the RandomForest tie-break.
- **Correlation with the target is modest** (max point-biserial |r| ~ 0.23 for
  Vocabulary / Distinct Operators), consistent with the moderate single-metric
  separability seen in the audit - no single metric is a label rule.
- The SHAP summary is an XGBoost stand-in; it is regenerated for the actual saved
  model in Phase 5.
